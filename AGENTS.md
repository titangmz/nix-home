# Working rules

- Read [STRUCTURE.md](STRUCTURE.md) before changing configuration.
- Keep only reusable NixOS additions in `modules/nixos/system`, exported as `nixosModules.desktop`. Base configuration, generated hardware settings, bootloader, users, hostname, networking, locale, `system.stateVersion`, and NixOS package sources remain machine-local under `/etc/nixos`; do not register machines in this repo. Preserve local settings when migrating. Keep greetd with the tuigreet text greeter in the shared system module, starting `start-hyprland` after authentication; keep users and automatic login machine-local. Build/evaluate system changes before activation. Keep `just switch` as a wrapper around portable `switch.sh`; keep `just switch-nixos` as a wrapper around `switch-nixos.sh`, which builds and activates the local `/etc/nixos/configuration.nix` before applying the desktop home profile.
- Keep `home.nix` small. Put packages, settings, and raw files in the owning module; personal identity belongs in `profiles/xray.nix`.
- Keep portable personal scripts as executable, non-hidden top-level files in `scripts/`; `modules/scripts` deploys them into `~/.local/bin` and owns that portable PATH entry. Do not take ownership of the entire `~/.local/bin` directory, so machine-local commands can coexist.
- Keep `home.nix` and the three platform outputs portable. NixOS desktop configuration belongs in `modules/nixos/desktop` and is imported only by `profiles/nixos-hyprland.nix`; a Linux platform check alone is not an opt-in. Keep `switch.sh` portable by default; select the complete NixOS workflow with `just switch-nixos`. Include portable-profile isolation assertions and a build of the desktop profile in flake checks.
- Keep GTK theming, the Bibata Modern Classic XCursor theme, and Thunar preferences in `modules/nixos/desktop`, guarded by `pkgs.stdenv.isLinux`. Enable Tumbler in `modules/nixos/system` for Thunar image thumbnails; keep `imv` as the image opener. Apply the cursor consistently to Hyprland, GTK, and XWayland, and keep software cursor rendering enabled to avoid NVIDIA hardware-cursor flicker. Enable NixOS DConf support for Home Manager GTK activation, provide user-session Xfconf D-Bus activation for Hyprland, and keep theme packages managed through Nix.
- Keep the bundled wallpaper and its service in `modules/nixos/desktop/wallpaper`. At service startup, select the first readable override in this order: `${config.xdg.dataHome}/wallpapers/override.png`, then `${config.xdg.dataHome}/wallpapers/override.jpg`; otherwise use the bundled image. Keep local overrides outside Nix. Hyprland imports its Wayland environment and starts the service. Keep `scripts/set-wallpaper` limited to readable PNG/JPEG files; copy the selected file atomically into the matching override, remove the opposite-format override, and restart the service.
- Keep Hyprland Lua configuration in `modules/nixos/desktop/hyprland`, Waybar configuration and CSS in `modules/nixos/desktop/waybar`, Rofi launcher styling in `modules/nixos/desktop/rofi`, and Mako notification styling in `modules/nixos/desktop/mako`. Use `modules/nixos/desktop/palette.nix` for shared colors; render color placeholders through its helper. Keep monitor identities and geometry in the optional untracked `~/.config/hypr/local_monitors.lua`; `setup-monitors.sh` creates it once without overwriting it. NixOS owns the Lua-compatible compositor package and portals. Hyprland startup commands own Waybar/Mako lifecycle, so do not enable duplicate services. Keep `just logout` on Hyprland's Lua dispatcher syntax.
- Preserve the three system output names: `x86_64-linux`, `aarch64-darwin`, `x86_64-darwin`.
- Keep `home.stateVersion` at `25.11` unless intentionally migrating. Update dependency pins only as part of a requested dependency change.
- Manage packages and plugins through Nix; general CLI packages belong in `modules/cli/default.nix`. Use `yq-go` for Mike Farah's `yq` command. Add plugin mappings only when their dependencies are configured; avoid duplicate bindings and initialization.
- Keep Atuin in `modules/shell/default.nix` with Home Manager's Zsh integration. Initialize it only in Zsh, since Bash hands off to Zsh; preserve the Up binding and keep automatic sync disabled unless requested.
- Keep WezTerm configuration in `modules/wezterm` using `xdg.configFile`; the user installs WezTerm separately. Use built-in Catppuccin Mocha and bundled fonts, with subtle transparency and macOS blur; stable Linux builds rely on compositor blur settings. Preserve default shortcuts and application Ctrl keys, including Neovim's Ctrl-Space; custom pane shortcuts use Ctrl-Shift-a as leader.
- Keep Kitty's user configuration in `modules/kitty/kitty.conf`, managed through Home Manager; keep the Kitty package system-managed on NixOS.
- Keep tmux's pane terminal at `tmux-256color` and advertise RGB for WezTerm's outer `xterm-256color`/`wezterm` terminals in `modules/tmux/tmux.conf`, preserving other terminal features. The tmux prefix is Ctrl-a.
- Keep Blink completion mappings in `modules/neovim/editing.nix`: Insert-mode `Ctrl-e` accepts and `Ctrl-q` dismisses suggestions, with built-in fallback when completion is inactive.
- Neovim layouts belong in `modules/neovim/workspace`; preserve editor splits and running jobs when hiding panes. Keep AI CLI behavior in `modules/neovim/ai`, credentials outside Nix, and plugin actions beside their owning modules. Use the separate `nixpkgs-codex` input only for Codex; its 26.05 branch preserves Intel macOS support. Preserve the main dependency pins for editor changes.
- Neovim checks must include `programs.nixvim.build.extraFiles` in the runtime path as well as the generated init file. Test layout/process behavior with a fake AI CLI; authenticated AI and native platform support need separate runtime verification.
- Keep one shell per Neovim session, with the same native terminal buffer in both views to preserve colors/prompts. Block terminal-input mode in the bottom view; `Space tt` opens its focused floating input window and double Escape closes it. Cargo commands use that same shell. Keep Lazygit in a separate centered floating overlay.
- Validate configuration changes with `nix flake check "path:$PWD"`; evaluate other platforms with `--all-systems --no-build`. Evaluation alone does not prove native runtime support.
- Format Nix with `nix fmt` from the checkout. Unlike `nix flake check`, `nix fmt` passes positional arguments to the formatter. Keep documentation concise and consistent with the actual files and commands.
- Use flake checks for validation: `switch.sh` applies the portable home, while `switch-nixos.sh` builds and activates the system before applying the desktop home. Keep Just recipes as wrappers around their owning scripts. `bootstrap-nixos.sh` enables `nix-command` and flakes through the shared NixOS module, preserves the generated local configuration as `/etc/nixos/machine.nix`, then delegates to `switch-nixos.sh`; `just bootstrap-nixos` remains its wrapper. Keep both workflows idempotent and covered by script tests. `just benchmark-switch` times one real portable switch with Hyperfine.
- Keep `README.md` limited to essential setup paths, command selection, and validation. Put detailed NixOS, desktop, shell, terminal, Neovim, and development guidance in the matching file under `docs/`. When structure, configuration, commands, or working rules change, update all affected Markdown files—including `STRUCTURE.md`, `README.md`, `AGENTS.md`, and relevant `docs/` guides—in the same change.
